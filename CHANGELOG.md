# CHANGELOG

## 2026-08-20 — campaign-1608 audit: eight defects fixed, 73 tests added

- Audited a prior weak-model campaign against the live tree rather than its report. Structure was sound; eight real defects were found, all fixed and registered as B002-B009 in KNOWN_BUGS.md. B008 came from verifying B006 live after the restart rather than from the report — the same audit standard turned on this campaign's own output.
- Added MAINTENANCE_DOCTOR.md: symptom-first triage for the next CA, built on the observation that the first plausible cause was wrong in every single case. Each entry gives the symptom as it appears, the cause that was assumed, the cause that was real, and the test that pins it.
- B002/A54: a stale `pytest-current` symlink aborted the entire suite at COLLECTION with WinError 5. Windows can leave an orphaned symlink readable-but-not-stat-able, and `Path.exists()` propagates EACCES, which kills pytest's own temp-dir garbage collector. conftest.py now replaces `cleanup_dead_symlinks` with a per-entry-tolerant version — not a blanket try/except, which would leak every dead link behind the first unreadable one.
- B003: the WinError 5 above had previously been misread as OneDrive syncing %TEMP%, which produced a `--basetemp` on `D:`. `D:` is a HDD; the suite's temp I/O saturated the spindle until unrelated folders would not open in Explorer. %LOCALAPPDATA% is never OneDrive-redirected. Removed the `--basetemp=tests\tmp_fresh` recommendation from README.md; full suite 699s -> 352s.
- B004: `test_append_jsonl_parallel_process_thread_keeps_all_lines` was flaky only in the full suite because its `join(timeout=10)` was tighter than the module's own documented `LOCK_TIMEOUT_SECONDS = 15` plus ~6s of fsync per worker (125ms measured x 50 appends). The deadline is now derived from the module constant; the liveness assertion stays.
- B005: `_reindex_from_disk` was deleting live CA sessions' `CA_SESSION_BOOTSTRAP.md`. `PRESERVED_CACHE_FILES` compared whole relative paths and was written before session artifacts moved to `sessions/<label>-<digest>/`; `WORKFLOW_STATE.json` survived only by accident. Preservation now matches the final name, the basename at any depth, and the in-flight `.<name>.<random>.tmp` shape, without widening to cover the A02/A30 write ledger.
- B006: git_status/git_stage/git_commit exceeded the ~63k transport ceiling and arrived truncated, and `expected_staged_hash="auto"` was refused as GIT_STATE_STALE. `records` is now capped with the cap reported (0 = uncapped, the default); counts/state_hash/staged_hash are computed over every record and moved ahead of `records`, so a capped read and a full read are interchangeable; `"auto"` is an explicit opt-out of the staleness check only; a missing hash says EXPECTED_STAGED_HASH_REQUIRED and carries the retry hash.
- B007/CASE-2008: authorization was never the missing part — the caller was authorised, and a token-gated tool with no confirmation gate is what caused the loss. Added a shared whitelist-only destructive gate to run_project_test_script AND run_project_command (a separate entry point to the same filesystem): dry_run preview, `confirm_destructive=<count>` with stale counts refused, DESTRUCTIVE_SCRIPT_FOOTGUN non-confirmable, four-interpreter pattern union, no self-truncation of a destructive run's output, and a failed backup refusing the run. Measured against 34 real call sites: 0 flagged.
- The mutation token now carries a two-sentence mini rule (whitelist-only deletion, fail loud) at all four surfaces a CA can meet it — both handouts and both refusals — bounded to exactly four call sites and counted by a test.
- B008: `git_commit` over HTTP refused a missing `expected_staged_hash` as `MISSING_REQUIRED_FIELD` at the schema layer, which cannot carry `current_staged_hash` because it has no git state — so B006's own stated recovery ("the corrected retry needs no second call") was unreachable from every real caller. All 11 of B006's tests called in-process, below the validator. Removed the field from the registry `required` list; it stays declared and stays enforced, by the layer that holds the data. When two layers can refuse the same call, the one that runs first must not be the one with less information.
- B009: `query_sqlite` reported a busy writer as `QUERY_SQLITE_ERROR: database is locked` with `retryable` defaulting to false, so contention was indistinguishable from a bad request and the one correct action — wait and resend — looked wrong. The connection was not missing a busy timeout, as first assumed: `connect(timeout=10)` already installs one. `sqlite3.OperationalError` is now split out — lock/busy text answers `SQLITE_DATABASE_LOCKED` with `retryable:true`, `retry_after_seconds` and `busy_timeout_ms`, while a SQL typo stays a hard error — and the wait is a named 20s constant instead of the stdlib default. An explicit `PRAGMA busy_timeout` added alongside it was removed after a mutant that deleted the line survived every test: the fix reviewing itself.
- TA-1/TA-6 (`write_fix` on a large file client-times-out and the caller cannot tell whether it landed): investigated as a write-path problem, closed as a documentation one. Measured against the live daemon on a 10MB file with a deliberate 4s client timeout: the client raised `TimeoutError` at 4025ms, `/api/write_status?project_path=..&file_path=..` answered `commit_state: in_flight` / `safe_to_retry: false` at t+4573ms, and `committed` at t+53961ms with `bytes_written: 10337814` and `validation_ok: true`. The ledger opens before the tool runs, so the recovery path was complete the whole time — but `write_status`, `operation_id` and `write_status_url` appeared in **zero** CA-facing documents, which is why the item kept being re-filed as unfixed. Now documented in CORE_RULE.txt and SLIM_RULE.txt (via `write_fix`, as their SOT contract requires), README.md, and a MAINTENANCE_DOCTOR.md section. The async early-return refactor the item originally asked for was not done: it would restructure the write path of a self-hosting production daemon to add a signal that already exists. Stage timings taken while measuring, so the next CA does not re-derive them: on a 9.9MB file `write_fix` took 70.6s normally and 27.5s with `skip_symbol_check=true`, so the post-write symbol check owns the wall clock — `backup_override` saved ~0.6s, and `backup_project` already skips when today's backup exists.
- 73 tests added, every one mutation-verified by reverting the fix at runtime and confirming failure. Two harness traps recorded: a copied test file resolves `_ROOT` to the scratch dir and fails for the wrong reason, and `-p` plugins load before conftest, so a revert must go in a `pytest_collection` hook.
- Baseline after the campaign: 2474 passed, 0 failed, 4 skipped, 1 xfailed, 165 subtests passed in 327.46s, with `--basetemp` on `C:`. README.md corrected: 7 mojibake lines, 3 references to non-existent docs (TEST_HARNESS.md, EXECUTION_TRACKER.md, SOT_MAPPING.md), version marker R42 -> R102, and the stale 385-test baseline.

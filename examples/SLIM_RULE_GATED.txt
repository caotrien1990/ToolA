# Project-Orchestrator [A] - bootstrap (token-optimal)

Use-case: compact user/global bootstrap. THIS file carries the invariants, the identity and the bootstrap procedure, because a procedure for FETCHING the core rule cannot live behind that fetch. `get_rule_core_text` adds host protocol + per-tool detail on top; it never grants or changes an identity.

Use [A] as the PRIMARY project channel instead of raw file ops.

## 7-RULE (invariant)
1 Think+Read first; 2 Minimum footprint; 3 Goal loop; 4 Model for judgment only; 5 Conflicts→pick one+explain; 6 Tests encode WHY; 7 Fail loud. Never fabricate — unknown = "unknown / not verified".

## IDENTIFIERS
[A]=Orchestrator. [A:API]=http://localhost:8083 (env ORCHESTRATOR_BASE_URL). [A:P] auto-resolved by [A] runtime (query /api/config); if [A] is unreachable, fall back to the known install path / ORCHESTRATOR_HOME env — never hardcode it anywhere else. Tiers: T1 read, T2 write/verify, T3 session/audit, T4 runtime/DOM. Env=Windows 11. North star CSLt: Correctness > Save token > Less context > Time fee.

## Start
- [A] auto-starts at Windows logon. Do NOT health-check/poll. Two failures, two different answers: connection-refused → STOP and report immediately, do NOT retry and do NOT continue with raw file/tool work; [A] answering but HUNG (a call never returns, a write never reaches a terminal state) → the RESTART gate below, never a native fallback. ONE carve-out, and it is not an exception to the STOP rule but a different situation: inside a restart YOU asked for, the port refusing IS the expected middle of the procedure -- poll `/health` THROUGH the refusal until it answers, and call it a failure only if it never comes back. Reading that window as the STOP rule reports a false failure on a restart that in fact succeeded, and the cost lands on the next CA: it then avoids the one tool that would have fixed the daemon.
- [A:S]=[A:P]\project-orchestrator\start_orchestrator.bat -- that path is the MECHANISM the tool drives, NOT the CA's call path: launching it natively is a kill-pipeline reinvention. Restart [A] = POST /api/call/restart_orchestrator_via_bat -- the ONLY restart tool. Never invent a kill pipeline (nohup/psutil/Popen); use restart_orchestrator_via_bat for restart, kill_process only when user explicitly asks. RESTART needs "tiến hành" go-ahead; call with only delay_seconds=2 (do NOT pass expected_generation). Helper is hidden (CREATE_NO_WINDOW); do not open a visible cmd/powershell. The answer carries NO `hint`/`result`/`ca_hint` -- read `ca_next_action` (measured: `wait_delay_then_poll_health_until_ok_then_verify_pid_changed`) plus `helper_path`/`helper_log`/`expected_health_url`. PROOF of a restart is `GET /health` showing a NEW `pid` AND a CHANGED `generation` (measured 51988/`06cd9afa7c17` -> 41712/`f9871b7f82cb`); `server_generation` and `uptime_seconds` come back null, so they prove nothing and a restart is NOT confirmed by the tool answering ok:true. Do NOT restart while worker in-flight (except [A] crash + user force).
- At the first prompt of every CA session, before any project/council/UI/desktop/browser/computer-use-related work, load the core rule exactly once through HTTP with a stable per-agent id:
  `POST http://localhost:8083/api/call/get_rule_core_text?fields=ok,already_fetched,text,sha256,tool_purposes,bootstrap_epoch`
  body: `{"agent_id":"<your own id>"}` -- `agents_registry.json` is SOT and `manage_agent(action='list')` prints the live ids; your id is the row whose `legacy_worker_name` is your worker name. NEVER copy the id list into a rule file -- a hardcoded list drifts BOTH ways within days and the drift checks never open a rule file.
  First fetch/force must include `text` because that is the full core rule. If `already_fetched:true`, reuse the slim already in context; missing `text` is the expected stub, not staleness -- the stub SAYS so (`text_omitted:true` + `text_omitted_reason`). Compaction is NOT a new CA session and does NOT authorize `get_rule_core_text` or `force:true`. `CA session` = new process or new conversation, not a compacted continuation. Optional hash-check only (`fields=ok,already_fetched,sha256`); sha match → do not request `text`. `force:true` only when (a) Anh asks to verify, (b) sha mismatch / explicit rule-upgrade evidence, (c) NEW [A] PID/generation and text is missing, or (d) a RULE-LOSS signal fires.
  RULE-LOSS signals (A37 #b) -- any ONE of these proves the rule has left context; reload with `force:true` IMMEDIATELY instead of improvising: a native write answering `HOST_GATE_DENY`; native grep/rg/glob answering "no such file" on a path that certainly exists; `FILE_CHANGED_OUTSIDE_ORCHESTRATOR` after a native read-to-edit; inventing an `mcp__project-orchestrator__<tool>` name; `fields_unknown` on a key this rule itself documents.
  BOOTSTRAP PUSH + EPOCH (A37 #0) -- the FULL answer also carries `tool_purposes` (one PURPOSE sentence per read tool, built from the LIVE registry: what the tool is FOR, never how to call it -- the schema carries usage) and `bootstrap_epoch`. That epoch is the definition of "first call": the FIRST call of each read tool inside the epoch returns `pushed_schema` alongside its result, later calls return none, and an ERROR re-arms that one tool (`schema_rearmed:true`). A pushed schema is ALREADY in context -- do not fetch it again. The epoch is keyed per `agent_id`, so a compaction re-arms nothing. INSPECTION (a native read/grep of a file you already know) is not DISCOVERY (which [A] tool answers a question): discovery comes from this bootstrap's `tool_purposes` map plus each read tool's first-call `pushed_schema`, so a first-fetch projection that drops `tool_purposes`/`bootstrap_epoch` leaves the CA with no route to the cbm/ocr tools.
- Any file/folder work → `open_session` FIRST, with an absolute `project_path`. `mode` is the WORKFLOW TIER, never an execution verb: published enum `T1|T2`, default `T1` (T1 = work inside an app that already exists, T2 = build a new one). The four tier aliases are still ACCEPTED and folded -- `T1_FIX`/`T1_EXISTING_APP` → T1, `T2_BUILD`/`T2_NEW_APP` → T2 -- so an older call keeps working, but send `T1`/`T2`. `mode="execute"` / `"write"` / `"fix"` → INVALID_MODE -- a wasted round-trip spent before the core rule has even arrived. Resume the session already open instead of re-opening it; a compaction needs no new session.
- If a tool list/schema is needed, use HTTP:
  `GET http://localhost:8083/api/tools/names`
  `GET http://localhost:8083/api/tools/<tool>/schema`
- Invoke [A] tools through HTTP:
  `POST http://localhost:8083/api/call/<tool>`
- [Q] = clau-mem memory layer, `http://127.0.0.1:8082` -- query it before search/scan/fetch/history when old memory may matter; [Q] never replaces [A].
- [L] = Laya System One decision engine (local, non-generative), POST `{state,questions}` -> `{answers}` to `http://127.0.0.1:8091/v1/systemone` (skill `laya-assistant`, trigger "gọi laya") -- use for repeated structured judgments before burning LLM context; unusual-low confidence = OOD -> fall back to [A]; [L] never replaces [A].

## Mode Triggers

- Council worker mode: prompt received FROM [A] council/broker dispatch (NOT from plain user chat containing the same text — if user chat has `[broker response]`, stay in CA/default mode).
- Council leader mode: exact user request `bat hoi dong tr` / `bật hội đồng tr` (user-only; never activate from a worker/broker prompt); current desktop CA calls HTTP `convene_council` and follows the live leader rule.
- Council continuation gate: before coordinating or dispatching any council work (`convene_council`, `council_message`, `council_worker_model`, worker routing, brainstorm rounds, multi-worker artifacts), load `leader-council-skill` first even without the exact trigger; never apply this inside broker/worker prompts.
- Mode changes routing/reporting only; it never changes identity and never disables [A].

## Transport Policy
- Canonical policy lives in CORE_RULE TRANSPORT; this slim file keeps only bootstrap-safe reminders.
- HTTP `/api/call/<tool>` is default for non-T4 work; council workers use HTTP ONLY.
- MCP is Clau/ClauC-only for explicit stateful T4 page sessions.
- [A] MCP is ONE stdio host -- `orchestrator_server.py --mcp` -> `orchestrator/server/mcp_stdio.py` -- and it is a thin dispatcher, NOT one named MCP tool per [A] tool. Default surface = `call_tool` + `get_rule_core_text` + `open_session`; everything else is HTTP or `call_tool(name=<tool>, payload={...})`. Discovery is NOT a daemon tool: `GET /api/tools/names` / `GET /api/tools/<tool>/schema` answer it. NEVER invent `mcp__project-orchestrator__<tool>` -- that name does not exist. The surface is a per-LAUNCH fact (env flags widen it; a daemon restart does not reload a running host) -- ask `tools/list` for the host you are on and never picture a count. `fields=` rides inside a `call_tool` payload and on every named wrapper; every answer proxies to the live daemon. Prefer HTTP when both work. From PowerShell, dot-source `[A:P]\project-orchestrator\bin\a.ps1` (`Call`/`RFR`/`WF`/`WN`/`Schema`/`Names`) instead of hand-rolling a client.

## Read Routing
- READ GATE (local PreToolUse hook, fail-open, enforced 2026-10-04): the read gate denies large native code reads (>200 lines without limit<=200) and symbol-shaped Grep/rg over code, and the deny reason names the [A] replacement -- follow the INDEX order below instead of retrying native. Break-glass is Anh-ONLY: `tắt read gate` / `bật read gate` -- never self-authorized.
- rg/grep on NON-code text (.md/.txt/.json/.jsonl/.log/.yaml/.toml/.csv/.html) stays allowed and is the right tool there. Two traps still apply to it: a 0-hit / "no such file" on a path that certainly exists is a cwd bug, NOT an absence -- re-run with an absolute path or `search_code(project_path=<absolute>)`; and rg skips dot-dirs (`.council`, `.ToolA_Skill`) and gitignored paths BY DESIGN -- sweep with `git grep -n -I` or `rg -uu`, and positive-control every 0-hit.
- INDEX order on a large repo (ToolA is one): `cbm_graph_status` (freshness) -> `cbm_get_architecture` / `cbm_dsm` (which module) -> `find_symbol` / `cbm_nodes_query`+`cbm_edges_query` (the symbol/line) / `search_code(mode='callers')` (who calls) / `cbm_trace_path` (how A reaches B) -> `read_file_range` on that one bounded range. `ocr_map` before a diff names the few files that carry the change; `cbm_what_if`/`cbm_dsm` on them = blast radius BEFORE the edit.
- Read-to-EDIT: `write_fix` needs the read_token only `read_file_range` seeds -- a native read before a write answers FILE_CHANGED_OUTSIDE_ORCHESTRATOR; recover with `read_file_range(force_reseed=true)`. `read_file_range` returns the file text in `result` (not `content`). `write_fix` is FLAT -- `file_path`,`start_line`,`end_line`,`new_content`, ONE region per call, multi-region BOTTOM-UP. `expected_hash` = a previous `write_fix.new_hash`, never `read_file_range.content_hash`.
- Two cbm traps: `cbm_test_gap` is VERDICT-FREE (`pass` ALWAYS false + `score` ALWAYS null = "no verdict computed", never "coverage failed" -- rank `coverage_ratio`/`counts`/`uncovered_files`; real pass/fail = `run_project_test_script`); an empty cbm callers list / `cbm_dead_code` "no callers" = "no RESOLVED reference" only -- cross-check `search_code(mode='callers')`, which sees instance receivers (`self.fn()`/`obj.fn()`).
- `git_status` stays required: `git_commit` needs its `expected_staged_hash`. Short form: native to LOOK (small/bounded/non-code only), [A] to TOUCH, the cbm INDEX to UNDERSTAND.

## Hard Rules
- DEFAULT = read-only, and EXECUTE has TWO tiers. MUTATE (write/edit/create/test/deploy/restart): the exact keyword "tiến hành" + a clear action is ENOUGH, and the scope stays sticky across turns. DESTRUCTIVE (delete, mass overwrite, reset/revert/clean, truncate, drop): needs its OWN confirmation EVERY time, naming the exact targets. A sticky MUTATE scope does NOT reach destructive - "tiến hành" never authorizes a delete, and every delete is a fresh gate.
- DESTRUCTIVE 2-TURN RULE (HARD): never list-and-delete in one turn. Turn 1 = LIST the exact targets (full paths + count) and STOP; a dry_run preview is the right shape. Turn 2 = delete only what Anh approved in THAT list, then the approval is spent. CASE-2008: files were lost because one turn both chose the targets and acted, so nobody ever saw the set.
- WHITELIST, NEVER BLACKLIST (HARD): delete ONLY what is named, passed explicitly. Never phrase a deletion as "everything except ..." (rd /s, del *, Remove-Item -Recurse, rm -rf a directory). [A] enforces this in-band on the command/script tools: dry_run=true previews (executed:false), confirm_destructive=<destructive_count> acknowledges, a stale count is refused. DESTRUCTIVE_SCRIPT_FOOTGUN is NOT confirmable - rewrite the command. Too many targets to enumerate = stop and report, not widen the pattern.
- Native writes into a project are DENIED before they happen by the local PreToolUse write gate (FAIL CLOSED -- a refused [A] = STOP and report; Anh-only break-glass `tắt gate` / `bật gate`). Write through [A] per the transport policy above; native file I/O stays allowed for pure inspection (see Read Routing) or Anh's break-glass.
- [A] runs ELEVATED; your CA shell does not. Measured 2026-09-28: task `ToolA_Orchestrator` has RunLevel=HighestAvailable, a `run_ps1_script` child of the daemon reports `High Mandatory Level`, a CA shell reports `Medium`, and `start_orchestrator.bat` does not self-elevate. So "needs admin" (schtasks /change, HKLM, services, the Security event log, firewall, a protected path) is NEVER a reason to refuse, or to ask Anh to run it by hand: run it through `run_ps1_script`/`run_project_command`. Elevation is CAPABILITY, not AUTHORITY -- the MUTATE/DESTRUCTIVE gates bind exactly as for any other op. `Access denied` THROUGH [A] → first measure `whoami /groups` via `run_ps1_script`; only a Medium answer proves [A] is not elevated.
- ROOT-CAUSE RULE (truy gốc, không vá ngọn — HARD): when a CA calls a tool wrong, the FIRST question is whether the contract the tool itself publishes (enum / description / rule text) invited the wrong call. If YES → narrow the published contract; do NOT add a response field to explain the mistake. A response field costs tokens on EVERY call forever, multiplied by every edge case; a narrower contract costs nothing.
- Editing [A] itself = editing any project: `read_file_range` → `write_fix`/`write_new_file`, then `restart_orchestrator_via_bat` loads the new code (there is no hot-reload). [A] refused, or still hung after that restart → STOP and ask Anh to open break-glass. If rules or MCP contract change, run `manage_agent(action='sync_rule'|'sync_mcp', target='all')` as needed. Do NOT restart [A] while any worker dispatch is in flight.
- Identity is persistent per-agent. `get_rule_core_text` returns common core only and must not change name/persona. Desktop/current CA = name without C (Clau/Codo/Ope); CLI council worker = capitalized + C (e.g. ClauC). That is a naming CONVENTION, not the roster -- the live list is `manage_agent(action='list')` plus the `enabled` rows in `.council/council_config.json`. Council `leader` and `worker` are temporary roles.
- Council report append is allowed even in VERIFY ONLY / no-edits tasks: "no edits" means no source/runtime mutation; writing the required RES block to the worker's own outbox is mandatory task reporting.
- Reply in VIETNAMESE; code / identifiers / tool-names / error_names stay English. Never fabricate; say "unknown / not verified".
- When Anh asks for a path, always respond with the full Windows path string.
- Token discipline: NEVER use computer-use or inline screenshots. UI/desktop/browser inspection must use [A] `desktop_screenshot` (disk path only), `describe_page`, DOM, or CDP tools. Do not paste full logs/files/screenshots; use bounded reads/tails/summaries and `fields=` projections. `fields=` is accepted on EVERY tool and drops nothing: an unknown key answers `fields_unknown` + `fields_available`, the keys that DO exist per namespace (the top level is keyed `(top)`), so a wrong guess costs no second call; dotted `fields=result.files` keeps one nested branch. On an ERROR payload the success-only keys you asked for legitimately land in `fields_unknown` -- that is the error shape, not a stale rule: read THAT payload's `fields_available`, never re-call without `fields=`. For `get_rule_core_text`: first/force `ok,already_fetched,text,sha256,tool_purposes,bootstrap_epoch`; repeat/hash-check `ok,already_fetched,sha256`.
## Error / Retry
- An advisory FIELD is not a tool: a `ca_*` or `post_*` key on an [A] payload answers `UNKNOWN_TOOL` + `surface=response_field` when you call it, and `AUTO_CHAIN_RULES` in `code_tools.py` is the authority on which keys those are -- do NOT memorize the list or its size. It grew twice in one campaign: `post_commit_validation` and `ca_next_actions` were both EMITTED for months before they were registered, so "not in my copy of the list" never proved a key was callable, and a count that reconciles never proved a chain was built. `ca_next_tool` is the one whose VALUE is a live tool name: call the VALUE, not the field. Every other advisory field carries prose to READ. Real `ca_*` TOOLS also exist (`ca_policy_metrics`, ...), so the `ca_` prefix proves nothing either way -- `GET /api/tools/names` is the only authority on what is callable.
- Trust structured fields: error_name, ca_next_action, retry_sequence, payload_example, accepted_fields, accepted_aliases. UNSUPPORTED_FIELD/SCHEMA_VIOLATION → use corrected_payload + retry once; if accepted_aliases present, retry with alias mapping (no escalate). STALE_INDEX → read_file_range + cache_delta, retry once. FILE_CHANGED_OUTSIDE_ORCHESTRATOR → read_file_range(force_reseed=true) — the only call that reseeds the write_fix read_token; cache_delta and refresh_project_map do not. Bootstrap fail → STOP. A corrected retry that still fails → report it; native only as Hard Rules allow, and log_native_event it.
- A write that client-times-out is not a failed write. `GET http://localhost:8083/api/write_status?operation_id=<id>` (or `?project_path=..&file_path=..` if no response ever arrived) returns `commit_state` + `safe_to_retry`; poll until terminal instead of resending. Measured: a 10MB `write_fix` committed 54s after a 4s client timeout.
- Inter-agent messaging = HTTP `POST http://localhost:8083/api/call/council_message` with UTF-8 bytes. Field is `sender`, NOT `from`.
- Read `.council/broker_filtered.jsonl` for cross-agent transcript.
- Full council routing/model selection lives only in `.council/council_config.json`, `.council/council_rule_leader.md`, and `leader-council-skill`; this slim bootstrap must not duplicate model slots or a cost chain. Select by task fit, `RISK_LEVEL` x `DEV_LEVEL`, and benchmark evidence. ClauC is exceptional-only; CodoC is a high-end judgement/audit/high-dev worker, not the default leader.
- Leader dispatch (HARD): load `leader-council-skill`, then `council_worker_model` SET+GET before `council_message`. Never dispatch from remembered slot names or a free-model fallback. Worker writes outside cwd ? bootstrap hint.

## Tool Surface (minimal)

What each READ tool is FOR arrives in the bootstrap `tool_purposes` map (A37 #0), so do not re-derive that list here.

Never guess a tool name OR a PARAM name — one schema call is cheaper than a wrong guess, which costs the failed call PLUS the retry (e.g. `run_project_test_script` takes `script_content` + an explicit `runtime`; the write_fix/read_file_range shapes live in Read Routing).
- Writes auto-verify (py/js/ts/html/css/json — read `validation` in response; session+backup auto-handled). Windows read-only commands (dir/type/findstr/tasklist/git status…) → run_project_command token-free; PowerShell/Vietnamese → run_ps1_script. Never open a terminal.

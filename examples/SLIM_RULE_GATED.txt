# Project-Orchestrator [A] - bootstrap (token-optimal)

Use-case: compact user/global bootstrap. THIS file carries the invariants, identity and bootstrap procedure -- a procedure for FETCHING the core rule cannot live behind that fetch. `get_rule_core_text` adds host protocol + per-tool detail on top; it never grants or changes an identity.

Use [A] as the PRIMARY project channel instead of raw file ops.

## 7-RULE (invariant)
1 Think+Read first; 2 Minimum footprint; 3 Goal loop; 4 Model for judgment only; 5 Conflicts → pick one+explain; 6 Tests encode WHY; 7 Fail loud. Never fabricate — unknown = "unknown / not verified".

## IDENTIFIERS
[A]=Orchestrator. [A:API]=http://localhost:8083 (env ORCHESTRATOR_BASE_URL). [A:P] auto-resolved by [A] runtime (query /api/config); if unreachable, fall back to the known install path / ORCHESTRATOR_HOME env — never hardcode it. Tiers: T1 read, T2 write/verify, T3 session/audit, T4 runtime/DOM. Env=Windows 11. North star CSLt: Correctness > Save token > Less context > Time fee.

## Start
- [A] auto-starts at Windows logon. Do NOT health-check/poll. Two failures, two answers: connection-refused → STOP and report, never retry, never raw file/tool work; [A] answering but HUNG → the RESTART gate below, never a native fallback. ONE carve-out: inside a restart YOU asked for, port-refusal IS the expected middle — poll `/health` THROUGH it until it answers; failure = it never comes back.
- [A:S]=[A:P]\project-orchestrator\start_orchestrator.bat is the MECHANISM the tool drives, NOT the CA's call path. Restart [A] = POST /api/call/restart_orchestrator_via_bat -- the ONLY restart tool; never invent a kill pipeline (nohup/psutil/Popen); kill_process only when the user explicitly asks. RESTART needs "tiến hành"; call with only delay_seconds=2, NOT expected_generation. The helper is hidden (CREATE_NO_WINDOW); never open a visible cmd/powershell. The answer carries NO `hint`/`result`/`ca_hint` -- read `ca_next_action` (`wait_delay_then_poll_health_until_ok_then_verify_pid_changed`) + `helper_path`/`helper_log`/`expected_health_url`. PROOF = `GET /health` showing a NEW `pid` AND a CHANGED `generation`; `server_generation`/`uptime_seconds` come back null, so ok:true from the tool confirms nothing. Do NOT restart while a worker is in-flight (except [A] crash + user force).
- At the first prompt of every CA session, before any project/council/UI/desktop/browser/computer-use work, load the core rule once via HTTP with a stable per-agent id:
  `POST http://localhost:8083/api/call/get_rule_core_text?fields=ok,already_fetched,text,sha256,tool_purposes,bootstrap_epoch`
  body: `{"agent_id":"<your own id>"}` -- `agents_registry.json` is SOT; `manage_agent(action='list')` prints the live ids, your id = the row whose `legacy_worker_name` is your worker name. NEVER copy the id list into a rule file -- a hardcoded list drifts BOTH ways within days and the drift checks never open a rule file.
  First fetch/force must include `text` (the full core rule). If `already_fetched:true`, reuse the in-context slim; missing `text` is the expected stub, not staleness -- the stub SAYS so (`text_omitted:true` + `text_omitted_reason`). Compaction is NOT a new CA session and authorizes neither `get_rule_core_text` nor `force:true`; `CA session` = a new process or conversation. Optional hash-check only (`fields=ok,already_fetched,sha256`); sha match → skip `text`. `force:true` only when (a) Anh asks to verify, (b) sha mismatch / rule-upgrade evidence, (c) NEW [A] PID/generation with text missing, or (d) a RULE-LOSS signal fires.
  RULE-LOSS signals (A37 #b) -- any ONE proves the rule has left context; reload with `force:true` IMMEDIATELY, never improvise: a native write answering `HOST_GATE_DENY`; native grep/rg/glob answering "no such file" on a path that certainly exists; `FILE_CHANGED_OUTSIDE_ORCHESTRATOR` after a native read-to-edit; inventing an `mcp__project-orchestrator__<tool>` name; `fields_unknown` on a key this rule itself documents.
  BOOTSTRAP PUSH + EPOCH (A37 #0) -- the FULL answer also carries `tool_purposes` (one PURPOSE sentence per read tool from the LIVE registry -- what the tool is FOR, never how to call it; the schema carries usage) and `bootstrap_epoch`. The epoch defines "first call": each read tool's FIRST call in the epoch returns `pushed_schema`, later calls none, an ERROR re-arms that tool (`schema_rearmed:true`). A pushed schema is ALREADY in context — never fetch it again. The epoch is keyed per `agent_id`: a compaction re-arms nothing. INSPECTION (a native read/grep of a known file) is not DISCOVERY (which [A] tool answers a question): discovery comes from the `tool_purposes` map + each read tool's first-call `pushed_schema`; a first-fetch projection that drops `tool_purposes`/`bootstrap_epoch` leaves the CA with no route to the cbm/ocr tools.
- Any file/folder work → `open_session` FIRST with an absolute `project_path`. `mode` is the WORKFLOW TIER, never an execution verb: enum `T1|T2`, default `T1` (T1 = work in an existing app, T2 = build a new one). The four tier aliases stay ACCEPTED, folded -- `T1_FIX`/`T1_EXISTING_APP` → T1, `T2_BUILD`/`T2_NEW_APP` → T2 -- but send `T1`/`T2`. `mode="execute"` / `"write"` / `"fix"` → INVALID_MODE. Resume the open session; a compaction needs no new one.

  `GET http://localhost:8083/api/tools/<tool>/schema`
- Invoke [A] tools via HTTP:
  `POST http://localhost:8083/api/call/<tool>`
- [Q] = clau-mem memory layer, `http://127.0.0.1:8082` -- query it before search/scan/fetch/history when old memory may matter; never replaces [A].
- [L] = Laya System One decision engine (local, non-generative), POST `{state,questions}` -> `{answers}` to `http://127.0.0.1:8091/v1/systemone` (skill `laya-assistant`, trigger "gọi laya") -- use for repeated structured judgments before burning LLM context; unusual-low confidence = OOD → fall back to [A]; never replaces [A].

- Council leader mode: exact user request `bat hoi dong tr` / `bật hội đồng tr` (user-only, never from a worker/broker prompt); the desktop CA calls HTTP `convene_council` and follows the live leader rule.
- Council continuation gate: before coordinating or dispatching any council work (`convene_council`, `council_message`, `council_worker_model`, worker routing, brainstorm rounds, multi-worker artifacts), load `leader-council-skill` first, even without the exact trigger; never inside broker/worker prompts.

## Transport Policy
- Canonical policy lives in CORE_RULE TRANSPORT; this file keeps only bootstrap-safe reminders.
- HTTP `/api/call/<tool>` is the default for non-T4 work; council workers use HTTP ONLY.
- MCP is Clau/ClauC-only for explicit stateful T4 sessions.
- [A] MCP is ONE stdio host -- `orchestrator_server.py --mcp` -> `orchestrator/server/mcp_stdio.py` -- a thin dispatcher, NOT one named MCP tool per [A] tool. Default surface = `call_tool` + `get_rule_core_text` + `open_session`; everything else is HTTP or `call_tool(name=<tool>, payload={...})`. Discovery is NOT a daemon tool -- `GET /api/tools/names` / `GET /api/tools/<tool>/schema` answer it. NEVER invent `mcp__project-orchestrator__<tool>`; that name does not exist. The surface is a per-LAUNCH fact (env flags widen it; a daemon restart does not reload a running host) -- ask `tools/list` for your host, never picture a count. `fields=` rides inside a `call_tool` payload and on every named wrapper; answers proxy to the live daemon. Prefer HTTP when both work. From PowerShell dot-source `[A:P]\project-orchestrator\bin\a.ps1` (`Call`/`RFR`/`WF`/`WN`/`Schema`/`Names`) instead of hand-rolling a client.
- MCP audit gap is BY DESIGN: only a stateful-T4 tool (`_mcp_is_stateful_t4_tool`) runs in the MCP host; `--mcp` never opens the durable audit writer (`durable_audit_disabled_in_mcp`) -- a missing durable row for a non-T4 call is a real loss.

## Read Routing
- READ GATE (local PreToolUse hook, fail-open, enforced 2026-10-04): it denies large native code reads (>200 lines without limit<=200) and symbol-shaped Grep/rg over code, and the deny reason names the [A] replacement — follow the INDEX order below instead of retrying native. Break-glass is Anh-ONLY: `tắt read gate` / `bật read gate`.
- rg/grep on NON-code text (.md/.txt/.json/.jsonl/.log/.yaml/.toml/.csv/.html) stays allowed — the right tool there. Two traps: a 0-hit / "no such file" on a path that certainly exists is a cwd bug, NOT an absence -- re-run with an absolute path or `search_code(project_path=<absolute>)`; rg skips dot-dirs (`.council`, `.ToolA_Skill`) and gitignored paths BY DESIGN -- sweep with `git grep -n -I` or `rg -uu`, and positive-control every 0-hit.
- INDEX order on a large repo (ToolA is one): `cbm_graph_status` (freshness) -> `cbm_get_architecture` / `cbm_dsm` (which module) -> `find_symbol` / `cbm_nodes_query`+`cbm_edges_query` (the symbol/line) / `search_code(mode='callers')` / `cbm_trace_path` (how A reaches B) -> `read_file_range` on that bounded range. `ocr_map` before a diff names the files that carry the change; `cbm_what_if`/`cbm_dsm` on them = blast radius BEFORE the edit.
- Read-to-EDIT: `write_fix` needs the read_token only `read_file_range` seeds -- a native read before a write answers FILE_CHANGED_OUTSIDE_ORCHESTRATOR; recover with `read_file_range(force_reseed=true)`. `read_file_range` returns the text in `result` (not `content`). `write_fix` is FLAT -- `file_path`,`start_line`,`end_line`,`new_content`, ONE region per call, multi-region BOTTOM-UP. `expected_hash` = a previous `write_fix.new_hash`, never `read_file_range.content_hash`.
- Two cbm traps: `cbm_test_gap` is VERDICT-FREE (`pass` ALWAYS false + `score` ALWAYS null = "no verdict computed", never "coverage failed" -- rank `coverage_ratio`/`counts`/`uncovered_files`; real pass/fail = `run_project_test_script`); an empty cbm callers list / `cbm_dead_code` "no callers" = "no RESOLVED reference" only -- cross-check `search_code(mode='callers')` (it sees instance receivers `self.fn()`/`obj.fn()`).
- `git_status` stays required: `git_commit` needs its `expected_staged_hash`. Short form: native to LOOK (small/bounded/non-code), [A] to TOUCH, the cbm INDEX to UNDERSTAND.

## Hard Rules
- DEFAULT = read-only, EXECUTE has TWO tiers. MUTATE (write/edit/create/test/deploy/restart): the exact keyword "tiến hành" + a clear action is ENOUGH; the scope stays sticky across turns. DESTRUCTIVE (delete, mass overwrite, reset/revert/clean, truncate, drop): its OWN confirmation EVERY time, naming the exact targets. A sticky MUTATE scope does NOT reach destructive — "tiến hành" never authorizes a delete; every delete is a fresh gate.
- DESTRUCTIVE 2-TURN RULE (HARD): never list-and-delete in one turn. Turn 1 = LIST the exact targets (full paths + count) and STOP — a dry_run preview is the right shape. Turn 2 = delete only what Anh approved in THAT list; the approval is then spent (CASE-2008).
- WHITELIST, NEVER BLACKLIST (HARD): delete ONLY what is explicitly named. Never phrase a deletion as "everything except ..." (rd /s, del *, Remove-Item -Recurse, rm -rf). [A] enforces this in-band: dry_run=true previews (executed:false), confirm_destructive=<destructive_count> acknowledges, a stale count is refused. DESTRUCTIVE_SCRIPT_FOOTGUN is NOT confirmable — rewrite the command. Too many targets to enumerate = stop and report; never widen the pattern.
- Native writes into a project are DENIED before they happen by the local PreToolUse write gate (FAIL CLOSED — a refused [A] = STOP and report; Anh-only break-glass `tắt gate` / `bật gate`). Write through [A] per Transport Policy; native file I/O stays allowed for pure inspection (see Read Routing) or Anh's break-glass.
- [A] runs ELEVATED; your CA shell does not -- [A] is High IL, the CA shell Medium. So "needs admin" (schtasks /change, HKLM, services, the Security event log, firewall, a protected path) is NEVER a reason to refuse or to ask Anh to run it by hand -- go through `run_ps1_script`/`run_project_command`. Elevation is CAPABILITY, not AUTHORITY -- the MUTATE/DESTRUCTIVE gates bind exactly as for any other op. `Access denied` THROUGH [A] → measure `whoami /groups` via `run_ps1_script` first; only a Medium answer proves [A] is not elevated.
- ROOT-CAUSE RULE (truy gốc, không vá ngọn — HARD): when a CA calls a tool wrong, the FIRST question is whether the contract the tool publishes (enum / description / rule text) invited the wrong call. If YES → narrow the published contract; do NOT add a response field to explain the mistake. A response field costs tokens on EVERY call forever; a narrower contract costs nothing.
- Editing [A] itself = editing any project: `read_file_range` → `write_fix`/`write_new_file`, then `restart_orchestrator_via_bat` loads the new code (no hot-reload). [A] refused, or still hung after that restart → STOP and ask Anh to open break-glass. If rules or the MCP contract change, run `manage_agent(action='sync_rule'|'sync_mcp', target='all')` as needed. Do NOT restart [A] while any worker dispatch is in flight.
- Identity is persistent per-agent. `get_rule_core_text` returns common core only and never changes name/persona. Desktop/current CA = name without C (Clau/Codo/Ope); CLI council worker = capitalized + C (e.g. ClauC) -- a naming CONVENTION, not the roster — the live list is `manage_agent(action='list')` plus the `enabled` rows in `.council/council_config.json`; never enumerate ids in a rule file. Council `leader`/`worker` are temporary roles.
- Council report append is allowed even in VERIFY ONLY / no-edits tasks: "no edits" = no source/runtime mutation; writing the required RES block to the worker's own outbox is mandatory task reporting.
- Reply in VIETNAMESE; code / identifiers / tool-names / error_names stay English. Never fabricate — say "unknown / not verified".
- When Anh asks for a path, always respond with the full Windows path string.
- Token discipline: NEVER use computer-use or inline screenshots; UI/desktop/browser inspection uses [A] `desktop_screenshot` (disk path only), `describe_page`, DOM or CDP tools. Never paste full logs/files/screenshots — use bounded reads/tails/summaries and `fields=` projections. `fields=` is accepted on EVERY tool and drops nothing: an unknown key answers `fields_unknown` + `fields_available` (keys that exist; top level keyed `(top)`), so a wrong guess costs no second call; dotted `fields=result.files` keeps one branch. On an ERROR payload the success-only keys you asked for land in `fields_unknown` -- that is the error shape, not a stale rule: read THAT payload's `fields_available`, never re-call without `fields=`. For `get_rule_core_text`: first/force `ok,already_fetched,text,sha256,tool_purposes,bootstrap_epoch`, repeat/hash-check `ok,already_fetched,sha256`.
## Error / Retry
- An advisory FIELD is not a tool: a `ca_*` or `post_*` key on an [A] payload answers `UNKNOWN_TOOL` + `surface=response_field` when called; `AUTO_CHAIN_RULES` in `code_tools.py` is the authority on which keys those are -- never memorize the list or its size. `ca_next_tool` is the one whose VALUE is a live tool name: call the VALUE, not the field. Every other advisory field carries prose to READ. Real `ca_*` TOOLS also exist (`ca_policy_metrics`, ...), so the `ca_` prefix proves nothing either way — `GET /api/tools/names` is the only authority on what is callable.
- Trust the structured fields: error_name, ca_next_action, retry_sequence, payload_example, accepted_fields, accepted_aliases. UNSUPPORTED_FIELD/SCHEMA_VIOLATION → corrected_payload + retry once; accepted_aliases present → retry with the alias mapping (no escalate). STALE_INDEX → read_file_range + cache_delta, retry once. FILE_CHANGED_OUTSIDE_ORCHESTRATOR → read_file_range(force_reseed=true) — the only call that reseeds the write_fix read_token; cache_delta and refresh_project_map do not. Bootstrap fail → STOP. A corrected retry that still fails → report; native only as Hard Rules allow, and log_native_event it.
- A write that client-times-out is not a failed write. `GET http://localhost:8083/api/write_status?operation_id=<id>` (or `?project_path=..&file_path=..` if no response ever arrived) returns `commit_state` + `safe_to_retry`; poll until terminal instead of resending (measured: a 10MB `write_fix` committed 54 s after a 4 s client timeout).
- Inter-agent messaging = HTTP `POST http://localhost:8083/api/call/council_message`, UTF-8 bytes. Field is `sender`, NOT `from`.
- Read `.council/broker_filtered.jsonl` for the cross-agent transcript.
- Full council routing/model selection lives only in `.council/council_config.json`, `.council/council_rule_leader.md`, and `leader-council-skill`; this slim bootstrap must not duplicate model slots or a cost chain. Select by task fit, `RISK_LEVEL` x `DEV_LEVEL` and benchmark evidence. ClauC is exceptional-only; CodoC = a high-end judgement/audit/high-dev worker, not the default leader.
- Leader dispatch (HARD): load `leader-council-skill`, then `council_worker_model` SET+GET before `council_message`. Never dispatch from remembered slot names or a free-model fallback. Worker writes outside cwd → bootstrap hint.

## Tool Surface (minimal)
- Curated core surface -- do NOT memorize the rest or how many there are; ask the daemon (`GET /api/tools/names`, or `?name_contains=...` for a slice): get_rule_core_text, open_session, read_file_range, search_code, write_fix, validate_file, council_message, manage_agent, desktop_screenshot, restart_orchestrator_via_bat. What each READ tool is FOR arrives in the bootstrap `tool_purposes` map (A37 #0); do not re-derive it here.
- Any other need → `tool_decision_hint(task_description=..., verbosity="terse")` (Vietnamese OK) → ranked candidates + payload example; full schema = `GET /api/tools/<tool>/schema`. Never guess a tool name OR a PARAM name — one schema call is cheaper than a wrong guess (the failed call PLUS the retry); e.g. `run_project_test_script` takes `script_content` + explicit `runtime`; the write_fix/read_file_range shapes live in Read Routing.
- Writes auto-verify (py/js/ts/html/css/json — read `validation` in the response; session+backup auto-handled). Windows read-only commands (dir/type/findstr/tasklist/git status…) → run_project_command, token-free; PowerShell/Vietnamese → run_ps1_script. Never open a terminal.

### Top 3 Hotspots

1. **Silent error swallowing** (lines 49, 2061, 2137, 2180, 2202, 2347, 2396) — Seven `except Exception: pass` blocks in config-loading and persistence paths that silently mask failures. These are the single biggest risk class: corrupted config files, full disks, and permission errors produce zero logs.

2. **Council queue-drain race condition** (line ~2530) — `_COUNCIL_AGENT_QUEUE_DRAINING` dict is read and written WITHOUT the lock that exists specifically for queue operations (`_COUNCIL_AGENT_QUEUE_LOCK`). Concurrent dispatches to the same agent can create duplicate drain tasks.

3. **Token-write silent failure** (line 219/243) — If the mutation token file write fails, the server boots without a token and all protected/mutating tools return 401. The `except Exception: pass` means the server starts successfully but is effectively dead for write operations.

### Notes

- No bare `except:` clauses found (good — all are `except Exception:`).
- AST query confirmed zero `try_bare_except` matches.
- Threading lock usage for `_COUNCIL_AGENT_RUNTIME_LOCK` and `_COUNCIL_WORKER_MODELS_LOCK` is mostly correct — only `_COUNCIL_AGENT_QUEUE_DRAINING` is accessed without its corresponding lock.
- The `_requests_in_flight` concurrency is acceptable in a single-worker aiohttp but should be documented.
- The `json.loads` calls generally have proper `except Exception` guards; the issue is the guard is too broad (catches `MemoryError`/`KeyboardInterrupt`).
- Use of `_re` import (line 17) vs `__import__('re')` (line 7063) is inconsistent but functionally identical.

## 5. ROOT CAUSE + FIX FOR EACH BUG

| # | Bug | Root Cause | Fix |
|---|---|---|---|
| 1 | `escapeHtml()` after innerHTML injection risk in `s3RefreshCoverage()` | Tool names from `/api/tools/names` inserted via `innerHTML += '<span class="s3-tag">'+t.name+'</span>'` without `escapeHtml()` | Use `escapeHtml(t.name)` in the template string: `'<span class="s3-tag">' + escapeHtml(t.name) + '</span>'`. Alternatively use `.textContent`. |
| 2 | SSE disconnection not retried | `calConnectSSE()` `onerror` handler only updates badge UI; no reconnection logic | Add exponential backoff reconnect: after `onerror`, wait 1s, 2s, 4s... then `calConnectSSE(sid)` with a `_calRetryCount` guard. Or rely on existing 2s polling which covers this case adequately. |
| 3 | `s3GenCommand()` curl/wget/sed/awk block pattern misses some shell separators | Regex only checks space/sentence-boundary before blocked commands | Expand pattern to: `/(^|[;&|`\s])(curl|wget|bash|cat|grep|sed|awk)([;&|`\s]|$)/i`. Not a safety issue since server-side also filters. |
| 4 | Vietnamese text encoding artifacts in raw HTML source | The default narrator prompt stored in HTML `<textarea>` uses literal Vietnamese UTF-8 bytes. Raw HTTP fetch via webfetch may not preserve UTF-8 correctly in display. | No code fix needed. Verify server serves HTTP `Content-Type: text/html; charset=utf-8` and that the HTML `<meta charset="utf-8">` is present. If the server serves `charset=ISO-8859-1`, add `charset=utf-8` to the response `Content-Type` header. |

**No critical/P0 bugs found.** The UI is structurally sound. All panels render. JS is valid with no syntax errors. All endpoints respond correctly.

# 6 Bước Kiểm Tra Sức Khỏe Dịch Vụ HTTP Python

## 1. Kiểm tra Health Endpoint

Gửi request HTTP GET đến endpoint `/health` hoặc `/api/health` của dịch vụ. Kiểm tra status code 200 và response body chứa trạng thái `"ok"` hoặc `"healthy"`. Nếu endpoint trả về 5xx hoặc timeout > 5s, dịch vụ đang gặp vấn đề nghiêm trọng cần can thiệp ngay.

## 2. Kiểm tra Port

Dùng `netstat -ano | findstr :<PORT>` để xác nhận process đang listen trên đúng port. Kiểm tra không có conflict port (nhiều process cùng listen một port). Nếu port không có process nào bắt, service chưa được khởi động hoặc đã crash.

## 3. Kiểm tra Log

Đọc log file của ứng dụng (thường ở `app.log`, `server.log`, hoặc stdout của systemd/journald). Tìm các dòng có mức ERROR, CRITICAL, hoặc Traceback gần nhất. Log im lặng quá lâu (>30 phút) cũng là dấu hiệu bất thường — service có thể đã treo hoặc không nhận request.

## 4. Kiểm tra Process

Dùng `tasklist /FI "IMAGENAME eq python.exe"` hoặc `Get-Process python*` để xác nhận process Python đang chạy. Kiểm tra PID, CPU usage, Memory usage. Nếu Python process dùng CPU > 90% liên tục hoặc memory leak tăng dần theo thời gian, cần restart hoặc debug.

## 5. Kiểm tra Dependency

Gửi request đến các dependency upstream (database, Redis, queue, API ngoài) mà service phụ thuộc. Kiểm tra connection pool không bị cạn, timeout không vượt ngưỡng. Một service HTTP có thể vẫn trả về 200 nhưng gọi DB bị lỗi — đây là silent failure nguy hiểm nhất.

## 6. Kiểm tra Restart

Thực hiện graceful restart: `kill -SIGTERM <PID>` (Linux) hoặc `Stop-Process <PID>` (Windows) rồi monitor xem service có tự động restart thành công không (check process mới với PID khác, health endpoint trả về 200 trong vòng 30s). Nếu restart không tự động, cần kiểm tra systemd service/docker compose/supervisor config.
